Calling automation

Agents don't choose who to call next. The system does.

A cash-on-delivery order isn't real until someone confirms it by phone. So calling is built as a pipeline, from the first ring to the customer who hasn't ordered in months.

Livein daily useBuiltfinished and tested in code, not switched on yet

  1. Smart Calling Live

    One shared queue for the whole floor: callbacks that are due, then new orders, newest first, then no-answers after 30 minutes. Three tries a day, then the order waits for tomorrow.

  2. No two agents on one customer Live

    Pulling a call claims it for three minutes. The order's status is read again before dialling, and agents are warned when a customer cancels often.

  3. One key per outcome Live

    Keys 1 to 5 log the result as that agent and move the order. In Power mode the next customer rings three seconds later.

  4. Browser softphone Live

    Calls run through our own Asterisk system. An incoming call opens the customer's open orders beside the page, so the agent can confirm without leaving it.

  5. Recordings and call log Live

    Every call is logged with its recording and tied to the customer. Missed calls get their own list, and call-back reminders appear in the phone.

  6. Coverage alerts Live

    Supervisors get a banner when too few phones are online, and an alert with sound when a customer's call goes unanswered.

  7. Retention queue Live

    Customers with no order in 60 days come back as calls. A later order is credited to the agent who called, within a set window.

  8. Robot Call Built

    Pending orders no agent has reached get an automated call with a recorded message. Pressing 1 confirms the order, and pressing 2 asks for a person.

  9. Missed-call SMS Built

    A caller nobody answered gets one text a day, so the call isn't simply lost.

  10. Campaign dialling Built

    A pacing engine dials only as many numbers as there are free agents, so nobody picks up to silence. If the agent's browser has gone, the call is never placed.

    How I work

    Three things this project taught me

    Fix the expensive problem, not the loud one

    I built fraud scoring before reconciliation because a held parcel gets complaints. The money leak nobody noticed was the bigger one.

    Training is part of shipping

    "Here's the login" changed nothing. Sitting next to people as they entered real orders did, and it showed me which problems were mine to fix.

    Only publish numbers you can defend

    You won't find a made-up catch rate here. Every figure comes from source code or test runs, and the case study shows how it was produced.
